# TermMeet — 함께 조작하고, 놓친 실습은 되감는 협업 터미널

> 여러 사람이 같은 터미널을 보고, 승인받은 한 명이 조작하고, 놓친 과정은 각자 되감아 보는 실습용 협업 프로그램.

ELEC462 시스템 프로그래밍 팀 프로젝트 · Team **[제출 전 팀번호 입력]** · **[팀원 1]**, **[팀원 2]**

**문서 상태: 구현 전 설계안.** 아래 기능, 명령, 파일 형식과 검증 기준은 개발 목표다. 구현 완료나 테스트 통과를 의미하지 않는다. 최종 제출 전 실제 구현 내용과 사용법에 맞게 갱신한다.

---

## 1. 프로젝트 소개

TermMeet는 조교와 학생, 팀원들이 하나의 터미널에서 함께 실습하도록 돕는 C 프로그램이다. 호스트가 실행한 셸의 출력을 여러 참가자에게 실시간으로 전달하고, 호스트의 승인에 따라 한 명씩 입력할 수 있다.

참가자가 설명을 놓쳤을 때는 **다른 사람의 진행을 멈추지 않고 자기 화면만 과거로 되돌린다.** 되감기 중에도 최신 출력은 계속 수신하며, 확인을 마치면 라이브 화면으로 복귀한다.

```text
A: 호스트/실습 진행             B: 조교/팀원                  C: 실습 참가자
./termmeet host               ./termmeet join <IP> 482173    ./termmeet join <IP> 482173

$ gcc main.c                  Ctrl+] r: 조작권 요청         설명을 놓침
[B의 요청을 승인]             승인 후 오류 수정             Ctrl+] b: 혼자 되감기
                              $ gcc main.c                  이전 수정 과정을 확인
                              $ ./a.out                     Ctrl+] l: 라이브 복귀

                              A와 B의 작업은 계속됨         C의 되감기는 다른 화면에 영향 없음
```

### 해결하려는 문제

| 상황 | 필요한 도움 | TermMeet의 해결 방법 |
|---|---|---|
| 조교에게 오류 질문 | 설명만으로 전달하기 어려운 실행 상태 확인 | 같은 터미널을 보면서 승인받아 직접 조작 |
| 팀 프로젝트 공동 작업 | 작업자를 바꾸면서 같은 셸 상태 유지 | 조작권 요청·승인·반납·회수 |
| 수업 시연을 놓침 | 전체 진행을 멈추지 않고 이전 과정 확인 | 참가자 개인 타임시프트와 라이브 복귀 |
| 처음 온 참가자가 현재 화면을 모름 | 세션의 앞부분부터 현재까지 동기화 | 과거 이벤트 수신 후 라이브 출력에 연결 |

### 프로젝트의 중심

**실시간 공유 → 승인 기반 공동 조작 → 개인 되감기와 복귀**를 하나의 실습 흐름으로 제공한다. 호스트 전용 조작과 명령 제안 승인은 추가 기능으로 둔다.

TermMeet는 격리된 실행 환경이나 임의의 위험 명령을 차단하는 보안 제품을 목표로 하지 않는다. 기본 사용 범위는 신뢰하는 팀원과 조교가 참여하는 실습용 LAN이다.

## 2. 주요 기능과 구현 우선순위

| 구분 | 기능 | 사용자 관점의 독립적인 가치 | 완료 기준 |
|---|---|---|---|
| **핵심 1** | **1:N 실시간 터미널 공유** | 여러 사람이 같은 실행 결과를 함께 확인 | 호스트 1명과 참가자 2명에게 같은 출력 전달 |
| **핵심 2** | **승인 기반 공동 조작** | 호스트가 허락한 사람에게만 입력 위임 | 요청·승인·반납·회수, 비조작자 입력 거부, 이탈 시 회수 |
| **핵심 3** | **참가자 개인 타임시프트** | 놓친 과정을 혼자 확인하고 현재 진행에 재합류 | 되감기 중 라이브 수신 유지, 다른 참가자에게 영향 없음, 복귀 후 화면 일치 |
| 추가 1 | 명령 제안·실행 전 승인 | 참가자가 제안한 한 줄 명령을 호스트가 확인 후 제출 | 승인 전에는 제안 내용이 PTY에 전달되지 않음 |
| 추가 2 | 호스트 전용 조작과 민감 입력 추정 알림 | 필요한 구간에 원격 조작을 잠그고 호스트가 직접 입력 | 수동 잠금·해제, 지원 조건에서 자동 잠금, 해제 후 자동 재위임 없음 |
| 추가 3 | 파일 녹화와 오프라인 재생 | 세션 종료 뒤에도 실습 과정을 복습 | 출력·시간·조작권 변화를 저장하고 별도 실행으로 재생 |
| 확장 | 동적 창 크기·화면 상태 체크포인트·상시 상태 표시줄 | 화면 대응과 탐색 속도 개선 | 핵심 기능을 검증한 뒤 지원 범위별로 추가 |

세션 생성·참가, 참가자 목록, 창 크기 확인은 핵심 기능을 지원하는 요소로 분류한다. 기능 수를 늘리기 위해 독립 핵심 기능으로 별도 계산하지 않는다. 추가 기능의 독립성 및 가산점 인정 여부는 최종 구현과 평가 기준에 따른다.

## 3. 지원 환경과 범위

| 항목 | 기본 구현 범위 |
|---|---|
| 운영체제 | Ubuntu 24.04 |
| 구현 언어 | C, gcc. 구현용 다른 언어와 셸 스크립트는 사용하지 않음 |
| 라이브러리 | glibc, pthread, ncurses |
| 접속 환경 | 로컬 테스트 또는 통신 가능한 LAN |
| 검증 규모 | 호스트 1명 + 참가자 2명을 필수 시연 규모로 설정 |
| 참가자 수 | 기본 상한 8명으로 설계. 그 이상의 지원 여부는 부하 검증 후 명시 |
| 터미널 | 같은 종류·호환 설정의 터미널, 같은 `TERM`, UTF-8 환경 |
| 화면 크기 | 기본 80열 × 24행. PTY와 각 사용자의 **실제 터미널 크기**를 일치시켜 검증 |
| 화면 프로그램 | 셸·컴파일·실행을 먼저 검증. `vim`, `top`, `gdb`는 프로그램별 검증을 통과한 범위만 지원 목록에 표시 |

초기 버전은 사용 중 창 크기를 고정한다. 크기가 달라지면 해당 사용자의 표시·입력을 일시 중단하고, 그 사용자가 조작자였다면 즉시 호스트에게 회수하며 epoch를 증가시킨다. 원래 크기로 복구한 후 전체 기록을 재적용한다. 최소 행·열을 계산하는 것만으로 모든 화면이 일치한다고 가정하지 않는다.

**기본 지원에서 제외하는 범위:** 서로 다른 터미널의 완전한 호환, 임의의 VT 제어 명령 지원, 무제한 길이의 세션, 무조건 즉시 가능한 라이브 복귀, 비밀 정보의 완전한 탐지·차단.

## 4. 기존 도구 및 이전 수업 프로젝트와의 관계

| 비교 대상 | 참고할 점 | TermMeet가 집중하는 부분 |
|---|---|---|
| tmate 등 터미널 공유 도구 | 실시간 공유와 읽기 전용/조작 접근 구분이라는 기존 사용 방식 | 세션 안에서의 요청·승인·반납과 실습 흐름 |
| asciinema | 터미널 기록·재생뿐 아니라 실시간 스트림 시청도 지원 | 양방향 공동 조작과 참가자별 개인 되감기를 같은 세션에 통합 |
| 2025년 봄 CoShell | ToDo·채팅·QR 등 터미널 기반 협업 보조 기능 | 하나의 PTY 공유와 입력 위임, 개인 타임시프트 |
| 2026년 봄 Web Streamer | 웹 스트리밍·실시간 채팅이라는 공유 경험 | 터미널 출력·입력을 다루는 협업과 실습 복습 |

개별 기능을 세계 최초라고 주장하지 않는다. 차별성은 **실습을 함께 진행하고, 도움을 주고받고, 놓친 과정을 각자 복습하는 사용 흐름**에 둔다. 공개 목록과 확인 가능한 README를 기준으로 비교하며 모든 과거 제출물의 비중복을 보장하는 표현은 사용하지 않는다.

기존 프로젝트의 소스 코드를 복사하지 않는다. 시스템 API 문서와 공개된 기능 설명을 참고하고, 프로그램 코드는 팀이 직접 구현한다. 라이브러리 사용과 참고 문헌은 구분해서 기록한다.

## 5. 빌드와 실행 방법 — 계획

아래 명령은 구현할 CLI의 명세다. 최종 제출 전 Ubuntu 24.04에서 실제 동작 여부를 확인한다.

### 빌드

```bash
sudo apt install build-essential libncurses-dev
make
```

링크 옵션은 `-lutil -lpthread -lncurses`를 사용한다. `make`, `make clean`을 제공하고, 컴파일 경고를 확인한다.

### 호스트

```bash
./termmeet host --port 7000 --max 8 --cols 80 --rows 24
./termmeet host --port 7000 --record session.tmrec --guard danger.txt
```

호스트는 세션 코드와 접속 정보를 표시한다. 코드는 참가할 세션을 확인하기 위한 값이며, 접속 후 참가자 확인·승인을 거친다. 코드만으로 강한 인증이나 통신 암호화를 제공한다고 설명하지 않는다.

### 참가자

```bash
./termmeet join 192.168.0.5 482173 --port 7000 --name helper
./termmeet join 127.0.0.1 482173 --name student
```

### 오프라인 재생 — 추가 기능

```bash
./termmeet play session.tmrec
./termmeet play session.tmrec --speed 2
```

| 옵션 | 의미 |
|---|---|
| `--port` | 접속 포트. 기본값 7000 |
| `--max` | 최대 참가자 수. 기본값 8 |
| `--cols`, `--rows` | 세션의 고정 화면 크기. 기본값 80열·24행 |
| `--name` | 참가자 표시 이름 |
| `--record` | 출력과 세션 이벤트를 지정 파일에 저장 |
| `--guard` | 제안 명령에서 주의할 패턴을 표시할 목록 파일 |
| `--speed` | 오프라인 재생 배속 |

`--guard`는 명령 제안 화면의 주의 표시를 위한 옵션이다. 패턴에 해당하지 않는 명령을 안전하다고 판정하거나, 일반 공동 조작에서 실행을 차단한다는 의미가 아니다.

## 6. 사용자 조작과 화면 상태

### 단축키

TermMeet 명령은 `Ctrl+]`를 누른 다음 키를 입력한다. 일반 공동 조작에서만 나머지 키를 셸로 전달한다.

| 키 | 동작 |
|---|---|
| `Ctrl+] r` | 조작권 요청 |
| `Ctrl+] d` | 조작권 반납 |
| `Ctrl+] t` | 호스트가 조작권 회수 |
| `Ctrl+] h` | 호스트 전용 조작 잠금·해제. 호스트만 사용 |
| `Ctrl+] c` | 한 줄 명령 제안 화면 열기 |
| `Ctrl+] b` | 개인 되감기 진입. 조작자라면 먼저 조작권 반납 |
| `Ctrl+] l` | 최신 기록을 따라잡고 라이브로 복귀 |
| `Ctrl+] s` | 참가자·조작자·기록 상태 확인 |
| `Ctrl+] q` | 세션 나가기. 호스트는 종료 확인 후 세션 종료 |
| `Ctrl+] Ctrl+]` | `Ctrl+]` 자체를 셸로 전달 |

되감기·오프라인 재생에서는 `Space`로 일시정지, `←`·`→`로 10초 이동, `+`·`-`로 배속 변경, `q`로 해당 화면을 닫는다. 임의 시점 탐색은 화면 상태 복원을 거친다.

### 참가자 화면 상태

| 상태 | 표시와 수신 | 셸 입력 |
|---|---|---|
| `SYNCING` | 접속·복귀를 위한 기록 수신 및 화면 재구성 | 금지 |
| `LIVE` | 현재 출력 표시 | 조작권이 있는 사용자만 허용 |
| `REVIEW` | 과거 시점 표시. 최신 이벤트는 계속 수신·저장 | 금지 |
| `COMMAND` | 상태·승인·명령 제안을 위한 로컬 명령 화면 | 셸로 보내지 않음 |

`COMMAND`에서는 라이브 출력이 명령 화면을 덮지 않도록 표시를 보류하고 계속 저장한다. 명령 화면을 닫으면 화면을 재구성해 라이브로 돌아간다. 초기 버전은 셸 화면 아래에 상태줄을 상시 합성하지 않는다.

## 7. 조작권과 입력 승인 설계

### 7.1 일반 공동 조작

1. 참가자가 조작권을 요청한다.
2. 호스트가 요청자와 현재 상태를 확인하고 승인한다.
3. 서버는 현재 조작자를 바꾸고 모두에게 알린다.
4. 현재 조작자의 입력만 PTY에 전달한다.
5. 반납·회수·연결 종료·되감기 진입·조작자의 화면 크기 불일치 시 조작권을 호스트에게 돌린다.

입력 허용 여부는 서버에서 최종 검사한다. 참가자 프로그램에서 키 전송을 막는 것만으로 권한을 구현하지 않는다.

조작권이 바뀔 때마다 `control_epoch`를 증가시키고 모든 `INPUT`에 해당 값을 포함한다. 이전 권한으로 늦게 도착한 입력은 거부한다. 회수 시 서버가 아직 PTY로 보내지 않은 해당 사용자의 입력도 폐기한다.

**이미 PTY에 전달한 입력이나 실행이 시작된 명령은 조작권 회수만으로 취소되지 않는다.** 일반 공동 조작은 승인받은 사용자에게 실제 셸 조작을 맡기는 모드다.

### 7.2 명령 제안·실행 전 승인 — 추가 기능

위험 패턴을 찾기 위해 원격 키 입력을 엿보는 방식 대신, 별도의 명령 제안 경로를 둔다.

1. 참가자가 `Ctrl+] c`로 로컬 입력창을 연다.
2. 제안할 한 줄 명령을 작성해 제출한다. 이 단계에서는 **어떤 바이트도 PTY로 보내지 않는다.**
3. 서버는 제어문자·개행이 없는 길이 제한 내 문자열만 받는다. 기본 상한은 1,024바이트다.
4. 호스트가 검토를 시작하면 먼저 조작권을 회수하고 제안자·명령 전체·주의 패턴을 확인한다. 모든 제안은 패턴 일치 여부와 관계없이 승인 대상이다.
5. 최신 셸 화면을 재구성해 **셸이 빈 프롬프트에서 명령을 받을 상태인지 직접 확인**한 뒤 승인한다. `COMMAND` 화면 뒤에 남은 과거 화면만 보고 판단하지 않는다. 확인할 수 없으면 거절한다.
6. 승인된 문자열과 줄 끝을 PTY에 전달한다. 검토 시작부터 제출 또는 거절까지 다른 참가자가 입력할 수 없도록 한다.

`vim`, 실행 중인 프로그램, 대화형 비밀번호 입력에 제안 명령을 보내지 않는다. 셸 프롬프트의 자동 인식이나 명령의 안전성 판정은 보장하지 않는다. 승인 메시지는 “제출 허용”을 뜻하며 실행 성공을 뜻하지 않는다.

`rm`, `sudo`, `mkfs`, `dd` 등은 주의 표시의 예시다. 별칭·스크립트·셸 확장까지 분석해 위험 실행을 모두 차단한다고 주장하지 않는다. 호스트는 제출할 내용을 직접 검토한다.

제안 명령의 본문은 기본 녹화에 저장하지 않는다. 승인·거절 여부와 요청자 ID 등 필요한 상태 변화만 기록한다.

### 7.3 호스트 전용 조작과 민감 입력 추정 — 추가 기능

호스트는 언제든 `Ctrl+] h`로 원격 조작을 잠글 수 있다. 잠금 상태에서도 참가자는 화면을 보거나 되감을 수 있으며, PTY 입력은 호스트만 허용한다.

자동 보조 기능은 외부 화면 터미널이 아닌 **자식 셸의 PTY 설정**을 조회한다. `ICANON` 켜짐·`ECHO` 꺼짐 조합은 민감 입력의 후보로 다룬다. 이는 비밀번호 여부를 알려주는 표준 신호가 아니며, 모든 비밀번호 입력을 탐지하지는 못한다.

- 셸 출력 수신 시, 입력 전달 직전, 주기적 점검 시 설정을 확인한다.
- 지원 조건을 감지하면 조작권을 호스트에게 회수하고 호스트 전용 잠금을 설정한다.
- “민감 입력 추정: 호스트만 조작”이라고 알린다.
- 설정이 돌아와도 원격 조작을 자동으로 재허용하지 않는다. 호스트가 직접 잠금을 해제하고 필요하면 다시 위임한다.
- 설정 변경과 입력 사이의 경합이 남을 수 있으므로 자동 감지를 보호 보장으로 설명하지 않는다.

**원시 키 입력은 기본적으로 기록하지 않는다.** 기록에는 출력과 조작권 변화만 남긴다. 따라서 감지 성공 여부에 의존해 비밀번호 키 입력의 저장을 막는 구조를 피한다.

호스트 전용 조작은 비공개 화면 모드가 아니다. **화면 출력의 전송과 기록은 계속된다.** 화면에 표시되는 토큰·파일 내용 등까지 숨겨주지 않으며, 민감한 작업은 공유 세션 밖에서 수행한다.

## 8. 전체 구조와 동시 처리

```text
호스트 키보드 ---------------------+
참가자 입력/요청 ---- TCP ---------+--> 호스트 메인 이벤트 루프
                                        |
                           권한·모드·epoch 확인
                                        |
                                        v
                                   PTY master <----> 자식 셸
                                        |
                                        v
                          순서가 있는 세션 이벤트 생성
                           |            |             |
                           v            v             v
                       호스트 표시   참가자 전송   메모리 이벤트 로그
                                                      |
                                               기록 작업 큐
                                                      |
                                                      v
                                             파일 기록 스레드
```

### 소유권과 역할

메인 스레드 하나가 nonblocking `poll()` 루프로 PTY·표준 입력·모든 소켓을 처리한다. 참가자별 읽기 스레드는 만들지 않는다. **소켓과 PTY별 읽기 담당은 하나**이며, 참가자 목록과 조작권 상태도 메인 스레드가 소유한다.

| 감시 대상 | 처리 |
|---|---|
| PTY 마스터 | 출력 수신, 이벤트 생성, 화면·참가자·메모리 로그에 전달 |
| 표준 입력 | 단축키 해석 또는 권한 확인 후 PTY 입력 큐에 추가 |
| 리슨 소켓 | 접속 수락과 초기 참가 절차 |
| 참가자 소켓 | 누적 수신 파싱, 요청 처리, 준비된 전송 버퍼 출력 |
| self-pipe | `SIGWINCH`, `SIGCHLD`, 종료 요청을 일반 실행 흐름에서 처리 |
| 기록 스레드 알림 pipe | 기록 실패·중단·완료 통지 |

파일 기록은 별도 pthread가 담당한다. 메인 스레드는 기록할 이벤트의 복사본을 상한이 있는 큐에 넣고, 기록 스레드는 파일 쓰기만 수행한다. 큐와 종료·오류 통지에 필요한 공유 데이터만 mutex·condition variable로 보호한다.

### 느린 연결과 기록 실패

- 부분 `read`·`write`, `EINTR`, `EAGAIN`, 연결 종료를 처리한다.
- 소켓 송신은 nonblocking으로 처리하고 참가자별 전송량·대기량 상한을 둔다.
- 과거 기록은 작은 청크로 보낸다. 전체 기록을 참가자별 송신 큐에 한꺼번에 복사하지 않는다.
- 따라잡지 못하거나 큐 상한을 넘는 참가자는 해당 연결만 종료하고 이유를 알린다.
- 기본 타임시프트 원본은 메인 스레드가 소유한 완전한 메모리 로그다. 파일 기록 지연에 의존하지 않는다.
- 파일 오류나 기록 큐 포화 시 **파일 녹화만 실패 상태로 중단**하고 이를 알린다. 무기록 상태를 정상 녹화처럼 표시하지 않는다. 메모리 타임시프트는 계속 가능하다.
- 메모리 로그는 기본 64 MiB 상한으로 설계한다. 이벤트 헤더·종료 메타데이터 공간을 미리 확보하고, 기록할 공간이 남은 만큼만 PTY 출력을 읽는다. 상한 전에 경고하고, 상한 도달 시 신규 입력과 PTY 읽기를 멈춰 출력 경로에 backpressure를 건 뒤 호스트에게 세션 종료와 새 세션 시작을 안내한다. 프로세스가 즉시 멈췄다고 가정하지 않으며, 이미 보존한 로그 앞부분을 조용히 버리지 않는다.

## 9. 개인 타임시프트와 화면 복원

### 9.1 기록할 정보

각 이벤트에 `seq`, 세션 시작 이후의 단조 증가 시간, 종류, 사용자 ID와 데이터를 붙인다. 출력뿐 아니라 조작권·호스트 잠금·참가자 정보도 같은 순서로 관리한다. 원시 키 입력은 저장하지 않는다.

### 9.2 늦은 참가자의 초기 동기화

1. 서버가 현재 확정된 이벤트 번호 `S`를 정하고 `SYNC_BEGIN(S)`를 보낸다.
2. 참가자가 기준 화면 상태로 초기화한 뒤 `1..S` 이벤트를 순서대로 적용한다.
3. 동기화 중 새로 발생한 `S+1..` 이벤트도 서버의 원본 로그에 보존한다.
4. 서버가 `SYNC_END(S)`를 보낸 뒤 `S+1`부터 라이브 이벤트를 순서대로 보낸다.
5. 참가자는 중복·누락을 확인하고 현재 시점에 도달한 뒤에만 `LIVE`로 전환한다.

세션 코드만 맞았다고 과거 기록을 보내지 않는다. 호스트의 참가 승인 이후 동기화를 시작한다.

### 9.3 되감기와 라이브 복귀

- 되감기 진입 요청을 서버가 처리하고 조작권이 반납된 것을 확인한 뒤 `REVIEW`로 전환한다.
- 수신 위치인 `live_seq`와 화면 재생 위치인 `play_seq`를 따로 관리한다.
- 과거 화면을 보는 동안에도 네트워크를 계속 읽고 최신 이벤트를 저장한다.
- 이전 시점으로 이동할 때는 기준 상태에서 목표 시점까지 이벤트를 대기 없이 적용해 화면을 재구성한다.
- 복귀할 때는 같은 방식으로 현재 기록까지 재구성하고, 그동안 추가된 이벤트를 따라잡은 뒤 `LIVE`로 바꾼다.
- `REVIEW`·`SYNCING` 중 셸 입력과 재생으로 발생한 터미널 응답을 PTY에 전달하지 않는다.
- 라이브 복귀 후에도 조작권은 자동으로 돌려주지 않는다.

전체 기록 재적용 비용은 로그 길이에 비례한다. 로그가 길면 복귀에 시간이 걸릴 수 있으며, 수신 처리와 화면 적용을 나누어 재구성 중에도 네트워크 이벤트가 쌓이도록 한다.

### 9.4 화면 복원의 조건과 한계

터미널 출력은 글자뿐 아니라 커서·색·스크롤 영역·화면 모드를 바꾸는 상태 기반 명령이다. **화면을 지우기만 하거나 파일 위치만 옮기는 것으로 과거 상태가 복원되지는 않는다.**

기본 구현은 동일한 실제 화면 크기와 호환되는 터미널을 사용하고, 색·커서·스크롤 영역·관련 모드를 검증된 초기 상태로 맞춘 뒤 첫 이벤트부터 적용한다. 시작 시 셸 실행 전 기준 상태를 설정하고, 종료 시 원래 터미널 설정을 복구한다.

이 방식은 지원 대상으로 정한 프로그램과 제어 시퀀스에서 검증한다. 모든 터미널 상태나 임의의 프로그램 출력을 완전히 재현한다고 약속하지 않는다. 재생 중 터미널 질의에 따른 응답이 현재 실행 중인 셸로 흘러들지 않도록 입력 경로를 분리한다.

동적 크기 변경은 확장 기능이다. 도입할 때는 `R` 이벤트로 논리 화면 크기를 기록하고, 크기 변경을 포함한 화면 상태를 재구성할 수 있는 렌더링 방식까지 함께 구현한다. `RESIZE` 이벤트를 저장하는 것만으로 크기가 다른 실제 터미널의 재현 문제가 해결되지는 않는다.

상태 체크포인트를 추가할 경우 글자 화면만 저장하지 않고 커서·색상·화면 모드 등 복원에 필요한 상태를 포함한다. 기본 버전은 불완전한 체크포인트를 사용하지 않고 처음부터 재적용한다.

## 10. 통신 프로토콜 — 계획

```text
type: 1 byte | payload_length: 4 bytes | payload: payload_length bytes
```

다중 바이트 정수는 네트워크 바이트 순서로 직렬화한다. C 구조체를 그대로 보내지 않는다. 프레임 payload 상한은 64 KiB, 출력 청크는 최대 4 KiB로 설계한다. 문자열 길이와 행·열·참가자 수를 별도로 검증한다.

| 메시지 | 방향 | 역할 |
|---|---|---|
| `HELLO` | 참가자 → 호스트 | 프로토콜 버전·코드·이름·터미널 정보·화면 크기 |
| `WELCOME` / `REJECT` | 호스트 → 참가자 | 참가 승인 또는 거절, 참가자 ID와 세션 설정 |
| `SYNC_BEGIN` / `HISTORY` / `SYNC_END` | 호스트 → 참가자 | 특정 `seq`까지의 과거 이벤트 전송 |
| `EVENT` | 호스트 → 참가자 | `seq`를 포함한 새 출력·조작권·잠금 등 세션 이벤트 |
| `INPUT` | 참가자 → 호스트 | 입력 바이트와 `control_epoch` |
| `REQ_CONTROL` | 참가자 → 호스트 | 조작권 요청 |
| `RELEASE_CONTROL` | 참가자 → 호스트 | 명시적인 조작권 반납 |
| `VIEW_MODE` / `MODE_ACK` | 양방향 | 되감기·동기화·라이브 상태 전환과 확인 |
| `CMD_PROPOSE` / `CMD_RESULT` | 양방향 | 명령 제안 및 승인·거절·제출 결과 |
| `STATUS_QUERY` / `STATUS` | 양방향 | 참가자·현재 조작자·잠금·기록 상태 조회 |
| `SIZE_REPORT` | 참가자 → 호스트 | 실제 터미널 크기 변경 알림. 기본 버전에서는 불일치 처리 |
| `BYE` / `ERROR` | 양방향 | 정상 종료 또는 명시적인 오류 |

호스트 승인·회수·잠금은 호스트의 로컬 UI로만 실행한다. 참가자가 호스트 권한의 명령을 전송해도 거부한다.

TCP 수신은 프레임 경계를 보존하지 않는다. 헤더와 본문을 누적 파싱하고, 여러 프레임이 한 번에 오거나 한 프레임이 나뉘어 오는 경우를 처리한다. 길이 초과·알 수 없는 타입·허용되지 않은 상태 전이는 거절한다.

## 11. 녹화 형식과 탐색 — 계획

```text
헤더:
  magic[6] = "TMREC2"
  version:u16 | rows:u16 | cols:u16
  start_unix_us:u64 | terminal_profile_length:u16 | terminal_profile:bytes

레코드:
  seq:u64 | elapsed_us:u64 | kind:u8 | actor_id:u32 | length:u32 | data:bytes
```

필드는 고정 크기와 명시적인 바이트 순서로 직렬화한다. `elapsed_us`는 `CLOCK_MONOTONIC` 기준의 세션 경과 시간이며, 실제 시각은 헤더의 별도 값으로 보관한다.

| kind | 내용 |
|---|---|
| `O` | PTY 출력 바이트 |
| `C` | 조작권 변경, 새 조작자와 epoch |
| `P` | 참가자 ID·표시 이름과 참가·퇴장 |
| `G` | 호스트 전용 잠금 및 해제 |
| `M` | 명령 제안의 승인·거절 등 상태. 명령 본문은 기본 미저장 |
| `R` | 크기 변경. 동적 크기 확장 버전에서만 사용 |
| `E` | 정상 세션 종료 |

`I` 형식의 원시 키 입력 레코드는 기본 형식에 넣지 않는다. 재생의 사용자 표시는 “이 구간의 조작권 보유자”를 뜻하며, 출력의 모든 바이트가 그 사용자의 명령에서 발생했다는 의미는 아니다.

### 탐색 처리

- 시간 색인은 목표 시간과 레코드 위치를 찾는 데 사용한다.
- `lseek`는 위치 조회·읽기 시작점 이동에 사용하며 화면 복원을 대신하지 않는다.
- 기본 버전은 초기 상태부터 목표 시점까지 관련 이벤트를 재적용한 뒤 정상 속도로 재생한다.
- 검증된 상태 체크포인트가 추가된 경우에만 해당 상태를 복원하고 이후 이벤트를 적용한다.
- 알 수 없는 버전·잘못된 길이·깨진 순서를 검사한다. 비정상 종료 파일은 마지막 완전한 레코드까지만 읽고 불완전 기록임을 알린다.

## 12. 시스템콜·라이브러리와 수업 연계

| 구현 영역 | 사용할 API | 실제 용도 |
|---|---|---|
| 프로세스와 PTY | `forkpty`, `execvp`, `waitpid` | 셸 실행, 종료 회수 |
| 터미널 | `tcgetattr`, `tcsetattr`, `ioctl` | raw 모드·복구, PTY 설정 조회, 화면 크기 |
| 시그널 | `sigaction`, `kill`, `pipe` | 종료·자식 종료·크기 변경 처리, 종료 시 자식 정리 |
| 네트워크 | `socket`, `bind`, `listen`, `accept`, `connect`, `setsockopt` | 세션 생성과 참가, 통신 |
| 다중 I/O | `poll`, `fcntl` | nonblocking 소켓·PTY와 이벤트 처리 |
| 파일 | `open`, `read`, `write`, `close`, `lseek` | 기록·재생·색인 조회 |
| 시간 | `clock_gettime` | 재생 시각과 세션 경과 시간 측정 |
| 스레드 | `pthread_create`, mutex, condition variable | 파일 기록 작업 분리 |
| UI | ncurses, 검증된 ANSI 제어 | 명령·재생 조작 화면과 셸 화면 관리 |

`forkpty`, pthread, ncurses 등을 모두 시스템콜로 세지 않는다. 최종 코드에서는 `socket`, `accept`, `read`, `write`, `ioctl`, `poll`, `open`, `lseek` 등 **실제로 의미 있게 사용한 서로 다른 시스템콜 5개 이상**을 근거와 함께 제시한다.

시그널 핸들러에서는 복잡한 UI·파일·mutex 작업을 하지 않고 플래그 설정과 self-pipe 통지 후 메인 루프에서 정리한다. 정상 종료와 처리 가능한 오류·시그널 종료에서 터미널을 복구한다. `SIGKILL` 등 정리 코드를 실행할 수 없는 종료까지 복구를 보장하지 않는다.

| 호스트 잠금 | 수동 잠금·민감 입력 추정·해제 | 참가자 입력 거부, 호스트만 조작, 자동 재위임 없음 |
| 파일 재생 | 정상·불완전 파일, 배속·중간 탐색 | 기록 검증과 상태 재구성, 손상 범위 명시 |

### 최종 발표 시연 흐름

1. 호스트 A와 참가자 B·C가 접속하고 같은 컴파일 오류를 본다.
2. B가 조작권을 요청한다. 승인 전 입력은 반영되지 않고 승인 후 수정할 수 있다.
3. C는 수정 과정을 놓쳤다고 가정하고 개인 되감기를 시작한다.
4. A·B는 컴파일과 실행을 계속한다. C의 화면만 이전 과정을 보여준다.
5. C가 라이브로 복귀하고 현재 화면에 합류한다.
6. 구현 완료한 경우에만 명령 제안 승인·호스트 잠금·오프라인 재생을 추가로 보여준다.
