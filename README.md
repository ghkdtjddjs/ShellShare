# TermMeet

**함께 조작하고, 놓친 실습은 나만 되감는 협업 터미널**

여러 사람이 하나의 터미널을 실시간으로 보고, 호스트가 승인한 한 명이 조작한다. 설명을 놓친 참가자는 다른 사람의 진행을 멈추지 않고 **자기 화면만 과거로 되감아** 보고, 다시 라이브로 돌아온다.

> **현재 상태: 설계 단계.** 구현이 진행되면 사용법, 지원 범위, 설계를 실제 동작에 맞게 갱신한다.

## 1. 한눈에 보기

```text
A: 호스트                      B: 조교/팀원                   C: 실습 참가자
./termmeet host                ./termmeet join <IP> 482173    ./termmeet join <IP> 482173
[B 입장 승인] [C 입장 승인]

$ gcc main.c                   Ctrl+] r: 조작권 요청          설명을 놓침
[B의 조작 요청 승인]           오류 수정                      Ctrl+] b: 나만 되감기
                               $ gcc main.c && ./a.out        수정 과정을 다시 확인
                                                              Ctrl+] l: 라이브 복귀
A와 B의 작업은 멈추지 않는다.  C의 되감기는 C의 화면에만 적용된다.
```

셸에서 실행하는 명령의 출력이 글자와 색, 커서 위치까지 그대로 공유된다.

## 2. 왜 만들었나

| 실습 상황 | 지금의 불편 | TermMeet |
|---|---|---|
| 조교에게 오류 질문 | 캡처를 주고받으며 설명을 반복 | 같은 터미널을 보고, 승인받아 직접 고친다 |
| 팀 프로젝트 | 한 명이 작업하면 나머지는 보기만 | 조작권을 주고받으며 같은 셸에서 이어서 작업 |
| 수업 시연을 놓침 | 진행을 멈춰 달라고 해야 한다 | 나만 되감아 확인하고 라이브로 복귀 |
| 터미널을 남에게 맡김 | 넘겨주면 무엇을 칠지 통제할 수 없다 | 명령 제안 승인, 호스트 전용 잠금으로 통제 |

## 3. 기능

**기능 7개 = 필수 3개 + 추가 4개.** 필수 3개는 11월 30일까지 반드시 완성해 시연하고, 추가 4개는 필수 기능을 통합한 뒤 이어서 구현한다.

### 필수 기능

| # | 기능 | 사용자가 하는 일 | 완료 기준 |
|---|---|---|---|
| 1 | **1:N 실시간 터미널 공유** | 호스트의 셸 화면을 여러 참가자가 동시에 본다 | 호스트 1명과 참가자 2명 이상에게 출력이 같은 순서로 전달되고 표시가 일치 |
| 2 | **승인 기반 공동 조작** | 참가자가 조작권을 요청하고, 호스트가 승인·회수한다. 조작은 한 번에 한 명 | 요청·승인·반납·회수, 비조작자와 이전 권한의 늦은 입력 거부, 조작자 이탈 시 호스트로 회수 |
| 3 | **개인 타임시프트** ★ | 라이브를 계속 받으면서 내 화면만 과거로 되감고, 끝나면 현재로 복귀한다 | 되감는 중 최신 이벤트 수신, 다른 참가자에게 영향 없음, 복귀 화면 일치, 재생이 현재 권한에 영향 없음 |

### 추가 기능

| # | 기능 | 사용자가 하는 일 | 완료 기준 |
|---|---|---|---|
| 4 | **참가 승인 (대기실)** | 참가자가 접속하면 호스트가 이름을 보고 입장을 허락하거나 거절한다 | 승인 전 과거 기록·현재 출력 미전송, 거절과 인원 초과 안내 |

## 5. 빌드와 실행

### 빌드

```bash
sudo apt install build-essential libncurses-dev
make            # termmeet 실행 파일 생성
make clean      # 빌드 결과 삭제
```

### 실행

```bash
# 호스트
./termmeet host [--port 7000] [--max 8] [--cols 80 --rows 24] [--record session.tmrec] [--guard danger.txt]

# 참가자
./termmeet join <호스트 IP> <세션 코드> [--port 7000] [--name 이름]

# 녹화 재생
./termmeet play session.tmrec [--speed 2]
```

| 옵션 | 의미 | 기본값 |
|---|---|---|
| `--port` | 접속 포트 | 7000 |
| `--max` | 최대 참가자 수 | 8 |
| `--cols`, `--rows` | 세션 화면 크기 (모든 사용자의 터미널을 이 크기로 맞춘다) | 80 × 24 |
| `--record` | 세션을 파일로 녹화 | 녹화 안 함 |
| `--guard` | 명령 제안 화면에서 주의 표시할 패턴 목록 | 기본 목록 |
| `--name` | 참가자 표시 이름 | 사용자 이름 |
| `--speed` | 재생 배속 | 1 |

같은 컴퓨터에서 시험할 때는 터미널 창을 여러 개 열고 `127.0.0.1`로 접속하면 된다.

### 단축키

라이브 화면에서 조작권을 가진 사용자의 키는 셸로 전달된다. TermMeet 명령은 **`Ctrl+]`를 누른 뒤 다음 키**로 쓰며, 되감기·명령 화면의 키는 셸로 가지 않는다.

| 키 | 동작 | 누가 |
|---|---|---|
| `r` | 조작권 요청 | 참가자 |
| `d` | 조작권 반납 | 조작자 |
| `t` | 조작권 회수 | 호스트 |
| `h` | 호스트 전용 잠금 켜기·끄기 | 호스트 |
| `c` | 한 줄 명령 제안 | 참가자 |
| `b` | 개인 되감기 시작 | 참가자 |
| `l` | 라이브 복귀 | 참가자 |
| `s` | 참가자·조작자·녹화 상태 보기 | 모두 |
| `q` | 나가기 (호스트는 세션 종료) | 모두 |
| `Ctrl+]` | `Ctrl+]` 자체를 셸로 보내기 | 조작자 |

되감기와 재생 화면에서는 `Space` 일시정지, `←` `→` 10초 이동, `+` `-` 배속, `q` 닫기.

## 6. 동작 원리와 구조

### 핵심 원리

1. 호스트가 `forkpty()`로 가상 터미널(PTY)을 만들고 그 안에서 셸을 실행한다.
2. 셸의 출력은 순서 번호(`seq`)가 붙은 이벤트가 되어 모든 참가자와 로그로 전달된다.
3. 조작권을 가진 사람의 입력만 PTY로 들어간다. 권한 검사는 서버에서 한다.
4. 터미널 화면은 **같은 초기 상태에서 같은 출력을 다시 적용하면 같은 상태로 재현된다.** 이 원리 하나로 늦은 참가자의 화면 동기화, 개인 되감기, 녹화 재생을 모두 구현한다. 재현 조건은 [12장](#12-화면-복원의-조건)에 정리했다.

### 구조와 스레드 모델

```text
                  ┌─────────────────────── 호스트 프로세스 ───────────────────────┐
호스트 키보드 ──▶ │                                                                 │
참가자 소켓 ────▶ │  메인 스레드: poll 이벤트 루프                                  │
                  │   - 권한·모드·epoch 확인 ──▶ PTY master ◀──▶ 자식 셸            │
                  │   - PTY 출력 → seq 이벤트 생성 → 호스트 화면 / 참가자 송신 큐   │
                  │                                 → 메모리 이벤트 로그            │
                  │                                 → 기록 큐 ──▶ 기록 스레드 ──▶ 파일 │
                  └─────────────────────────────────────────────────────────────────┘

                  ┌─────────────────────── 참가자 프로세스 ───────────────────────┐
                  │  수신 스레드: 소켓 읽기 → 프레임 파싱 → 로컬 이벤트 로그 추가   │
                  │                    (짧은 mutex 잠금 + 수신 알림 pipe)         │
                  │  화면 스레드: 키보드·알림 pipe poll, 모드 전환, 화면 적용, 송신  │
                  └─────────────────────────────────────────────────────────────────┘
```

**호스트**

- **메인 스레드 하나**가 nonblocking `poll()`로 PTY, 표준 입력, 리슨 소켓, 모든 참가자 소켓, self-pipe를 처리한다. 참가자 목록, 조작권, 메모리 로그는 메인 스레드만 수정하므로 권한 상태에 경합이 생기지 않는다.
- **기록 스레드**가 파일 쓰기만 담당한다. 메인 스레드는 이벤트 복사본을 상한이 있는 큐에 넣고, 큐는 mutex와 condition variable로 보호한다. 기록이 느려도 공유와 조작은 멈추지 않는다.

**참가자**

- **수신 스레드**는 소켓의 유일한 읽기 담당이다. 프레임을 파싱해 로컬 이벤트 로그에 추가하고, 현재 세션 상태와 수신 위치를 갱신한 뒤 알림 pipe로 화면 스레드를 깨운다. 화면에는 직접 쓰지 않는다.
- **화면 스레드**는 `poll()`로 표준 입력과 알림 pipe를 함께 감시하며 키보드 처리, 모드 전환, 화면 적용, 소켓 송신을 맡는다. 송신 큐가 남아 있으면 같은 루프에서 `POLLOUT`도 감시해 부분 전송을 이어 보낸다. 소켓 쓰기를 이 스레드로 한정해 프레임이 섞이지 않게 한다.
- **나누는 이유:** 되감기나 복귀로 긴 로그를 다시 그리는 동안에도 네트워크를 계속 읽어야 한다. 읽기가 멈추면 호스트 쪽 송신 큐가 차서 연결이 끊긴다.
- **잠금을 짧게:** 로컬 로그는 추가 후 바뀌지 않는 청크로 관리한다. 화면 스레드는 mutex 안에서 필요한 이벤트를 작은 묶음으로 복사하고, 잠금을 푼 뒤 그린다. 재생도 묶음 단위로 나눠서, 묶음 사이에 키보드·수신 알림·종료 요청을 처리한다.
- **공유 데이터:** 로컬 로그, `live_seq`, `live_session_state`, 연결 상태를 mutex로 보호한다. `play_seq`와 `replay_state`는 화면 스레드만 관리한다.
- condition variable은 호스트 기록 큐 대기에 쓴다. 키보드에서 대기하는 `poll`은 condition variable로 깨울 수 없으므로 참가자 쪽은 알림 pipe를 쓴다.

## 7. 조작권과 입력 경로

1. 참가자가 `REQ_CONTROL`을 보낸다.
2. 호스트가 로컬 UI에서 승인한다. 승인·회수·잠금은 호스트 로컬 UI에서만 실행되며, 참가자가 보낸 호스트 권한 요청은 거부한다.
3. 서버는 현재 조작자를 바꾸고 `control_epoch`를 1 올린 뒤 모두에게 알린다.
4. 모든 `INPUT`에는 보낸 쪽이 알고 있는 `control_epoch`가 들어 있다. 서버는 다음을 **모두** 만족할 때만 PTY 입력 큐에 넣고, 실제 PTY에 쓰기 직전에도 다시 확인한다.
   - 입장이 승인된 현재 조작자다.
   - epoch가 현재 값과 같다.
   - 서버가 확인한 그 사용자의 모드가 `LIVE`다.
   - 화면 크기가 세션 크기와 같다.
   - 호스트 전용 잠금과 명령 검토 잠금이 꺼져 있다.
5. 반납, 회수, 연결 종료, 되감기 진입, 조작자의 화면 크기 불일치가 생기면 조작권을 호스트에게 돌리고 epoch를 올린다. 그 사용자의 아직 PTY로 보내지 않은 입력은 버린다.

참가자 프로그램에서 키 전송을 막는 것은 편의일 뿐이고, 권한은 서버에서 최종 판정한다. 호스트 전용 잠금 중에도 호스트의 로컬 입력은 허용한다.

### 현재 권한과 과거 표시의 분리

- `live_session_state`: 서버가 알려준 **현재** 조작자, epoch, 잠금, 모드.
- `replay_state`: 되감기 화면에 보여줄 **그 시점의** 조작자 표시.

과거의 조작권 변경(`C`)이나 잠금(`G`) 이벤트를 재생해도 `replay_state`만 바뀌고 현재 입력 권한은 바뀌지 않는다.

### 모드 전환

모드 변경은 `VIEW_MODE`로 요청하고 서버의 `MODE_ACK`로 확정한다. 전환을 요청한 순간부터 셸 입력을 막고, 합의한 기준 `seq`까지 화면을 적용한 뒤 `LIVE` 확인을 받아야 입력이 다시 열린다. `MODE_ACK`는 조작권 부여가 아니며, 라이브로 돌아온 뒤 조작권은 따로 요청한다.

## 8. 참가 승인과 초기 동기화

### 참가 승인

1. 참가자가 `HELLO`(프로토콜 버전, 세션 코드, 이름, `TERM`, 화면 크기)를 보낸다.
2. 서버는 코드, 인원, 화면 크기를 검사한다. 통과하면 참가자를 **대기 상태**로 두고 호스트에게 입장 요청을 표시한다.
3. 호스트가 승인하면 `WELCOME`(참가자 ID, 세션 설정), 거절하면 `REJECT`(이유)를 보낸다.
4. 대기 상태에서는 어떤 화면 출력이나 과거 기록도 보내지 않는다.

### 초기 동기화

1. 서버가 현재 확정된 이벤트 번호 `S`를 정하고 `SYNC_BEGIN(S)`와 그 시점의 조작권·epoch·잠금 상태 스냅샷을 보낸다. 참가자는 이 스냅샷으로 `live_session_state`를 초기화한다.
2. `1..S` 이벤트를 작은 청크(`HISTORY`)로 보낸다. 전체 로그를 송신 큐에 한꺼번에 복사하지 않고, 큐가 비는 만큼 다음 청크를 넣는다.
3. 동기화 중 새로 생긴 `S+1..` 이벤트는 메모리 로그에 남아 있으므로, `SYNC_END(S)` 뒤에 `S+1`부터 이어서 보낸다.
4. 참가자는 `seq`의 중복과 누락을 확인하고, 기준까지 적용한 뒤 뒤이어 받은 이벤트를 따라잡는다. 그다음 `LIVE` 전환을 요청하고 `MODE_ACK`를 받으면 `LIVE`로 확정한다.

## 9. 개인 타임시프트

### 참가자 화면 모드

| 모드 | 화면 | 셸 입력 |
|---|---|---|
| `SYNCING` | 접속·복귀를 위해 로그를 적용하는 중 | 금지 |
| `LIVE` | 현재 출력 표시 | 조작권이 있을 때만 |
| `REVIEW` | 과거 시점 표시. 최신 이벤트는 계속 수신해 쌓아 둠 | 금지 |
| `COMMAND` | 상태 보기, 명령 제안 같은 로컬 화면. 라이브 출력은 표시를 보류하고 계속 쌓음 | 셸로 보내지 않음 |

### 되감기와 복귀

- 되감기를 요청하는 즉시 셸 입력을 막는다. 서버가 조작권을 회수하고 `MODE_ACK`로 확인하면 `REVIEW`로 바꾼다.
- 수신 위치 `live_seq`(수신 스레드가 갱신)와 재생 위치 `play_seq`(화면 스레드가 관리)를 따로 둔다.
- 과거 시점으로 이동할 때는 화면을 초기 상태로 맞추고 1번부터 목표 시점까지 이벤트를 대기 없이 적용한 뒤, 그 시점부터 원래 속도나 배속으로 재생한다.
- 복귀할 때는 `SYNCING`으로 바꾸고 서버와 기준 `seq`를 정한다. 그 기준까지 재구성하고 추가로 받은 이벤트를 따라잡은 뒤, `LIVE` 확인을 받아 확정한다.
- 복귀해도 조작권은 자동으로 돌려주지 않는다.

### 재생 중 터미널 응답 차단

출력 중에는 커서 위치 질의(`ESC[6n`) 같은 **터미널에게 묻는 명령**이 섞여 있다. 재생하면 참가자 터미널이 그 답을 표준 입력으로 보낼 수 있다.

- `SYNCING`, `REVIEW`, `COMMAND`에서는 표준 입력을 셸로 보내지 않고, 로컬 조작 키와 터미널 응답을 구분해 처리한다.
- 라이브 복귀 전에 재생으로 생긴 응답과 남은 입력을 정리한다. 입력 버퍼를 한 번 비우는 것만으로 늦게 도착하는 응답까지 막힌다고 보지 않고, 전환 직후 응답이 셸 명령에 섞이지 않는지 따로 검증한다.

## 10. 명령 제안·실행 전 승인

키 입력을 엿봐서 위험 명령을 찾는 대신, 셸과 분리된 **제안 경로**를 둔다.

1. 참가자가 `Ctrl+] c`로 로컬 입력창을 열고 한 줄 명령을 쓴다. 이 단계에서는 PTY로 아무것도 보내지 않는다.
2. 서버는 제어문자와 개행이 없고 1,024바이트 이하인 문자열만 받는다 (`CMD_PROPOSE`).
3. 호스트가 검토를 시작하면 서버는 먼저 조작권을 회수하고 명령 검토 잠금을 걸어, 검토부터 제출까지 다른 입력이 끼어들지 않게 한다.
4. 호스트는 제안자, 명령 전체, `--guard` 패턴 일치 여부(예: `rm -r`, `sudo`, `mkfs`, `dd`)를 본다. 패턴과 관계없이 모든 제안은 승인 대상이다.
5. 호스트는 최신 화면에서 **셸이 빈 프롬프트에서 명령을 기다리는지 직접 확인**한 뒤 승인한다. 확인할 수 없으면 거절한다. `vim`이나 실행 중인 프로그램, 비밀번호 입력 화면에는 제출하지 않는다.
6. 승인되면 문자열과 줄 끝을 PTY에 쓰고 `CMD_RESULT`로 결과를 알린다.

녹화에는 명령 본문을 남기지 않고 제안자, 승인·거절 여부만 남긴다.

## 11. 호스트 전용 잠금과 민감 입력 추정

- 호스트는 `Ctrl+] h`로 원격 조작을 잠근다. 잠금 중에도 참가자는 화면을 보고 되감을 수 있지만 PTY 입력은 호스트만 가능하다.
- **자동 잠금:** 호스트는 PTY master에 `tcgetattr()`를 해서 자식 셸 쪽 터미널의 입력 모드를 읽는다. `sudo`, `passwd` 같은 비밀번호 입력은 보통 `ICANON` 켜짐, `ECHO` 꺼짐 상태이고, `vim`처럼 화면 전체를 쓰는 프로그램은 둘 다 끈다. 이 차이로 민감 입력을 **추정**한다.
- 확인 시점: PTY 출력을 받을 때, 원격 입력을 PTY에 쓰기 직전, 그리고 주기적으로.
- 추정되면 조작권을 호스트로 회수하고 잠금을 켠 뒤 "민감 입력 추정: 호스트만 조작"을 알린다.
- 입력 모드가 원래대로 돌아와도 잠금은 자동으로 풀리지 않는다. 호스트가 직접 해제하고 필요하면 다시 위임한다.
- **원시 키 입력은 녹화하지 않는다.** 그래서 자동 추정의 성공 여부와 관계없이 비밀번호 키 입력이 기록에 남지 않는다. 잠금은 입력 권한을 제한하는 기능이고, 화면 출력은 계속 공유·기록된다.

## 12. 화면 복원의 조건

터미널 출력은 글자뿐 아니라 커서, 색, 스크롤 영역, 화면 모드를 바꾸는 명령의 연속이다. 화면을 지우거나 파일 위치만 옮겨서는 과거 상태가 복원되지 않는다. 그래서 다음 조건을 지킨다.

- 시작할 때 셸 실행 전에 색, 커서, 스크롤 영역, 관련 모드를 정해진 초기 상태로 맞춘다. 재적용도 항상 이 초기 상태에서 시작한다.
- 모든 사용자가 같은 `TERM`과 호환 터미널을 쓰고, 실제 터미널 크기를 세션 크기와 같게 맞춘다. 출력 바이트를 그대로 전달하는 구조라서 크기가 다르면 자동 줄바꿈과 스크롤 위치가 어긋나기 때문이다.
- 크기가 달라지면(`SIGWINCH`로 감지) 그 사용자의 표시와 입력을 멈추고, 조작자였다면 호스트로 회수한다. 원래 크기로 돌아오면 전체 로그를 다시 적용한다.
- `vim`, `top`, `gdb` 같은 전체 화면·대화형 프로그램은 재현을 검증한 것만 지원 목록에 올린다.
- 종료할 때는 원래 터미널 설정을 복구한다.

**확장:** 사용 중 크기 변경을 지원하려면 참가자 쪽에 화면 버퍼를 가진 터미널 해석기가 필요하다. 이 경우 크기 변경 이벤트(`R`)를 기록하고, 해석기의 화면 상태로 체크포인트도 만들 수 있다. 기본 버전은 체크포인트 없이 처음부터 재적용한다.

## 13. 통신 프로토콜

```text
type: 1 byte | payload_length: 4 bytes | payload: payload_length bytes
```

- 다중 바이트 정수는 네트워크 바이트 순서로 직렬화한다. C 구조체를 그대로 보내지 않는다.
- 프레임 payload 상한 64 KiB, 출력 청크 최대 4 KiB. 문자열 길이, 행·열, 참가자 수를 따로 검증한다.
- TCP는 메시지 경계를 보존하지 않으므로 헤더와 본문을 누적 파싱한다. 길이 초과, 알 수 없는 타입, 허용되지 않은 상태 전이는 `ERROR` 후 연결을 끊는다.

| 메시지 | 방향 | 역할 |
|---|---|---|
| `HELLO` | 참가자 → 호스트 | 프로토콜 버전, 세션 코드, 이름, `TERM`, 화면 크기 |
| `WAITING` | 호스트 → 참가자 | 입장 승인 대기 중 |
| `WELCOME` / `REJECT` | 호스트 → 참가자 | 입장 승인(참가자 ID, 세션 설정) 또는 거절 이유 |
| `SYNC_BEGIN` / `HISTORY` / `SYNC_END` | 호스트 → 참가자 | 기준 `seq`와 현재 상태 스냅샷, 그 시점까지의 과거 이벤트 |
| `EVENT` | 호스트 → 참가자 | `seq`가 붙은 새 이벤트 (출력, 조작권, 잠금, 참가자 변화) |
| `INPUT` | 참가자 → 호스트 | 입력 바이트와 `control_epoch` |
| `REQ_CONTROL` / `RELEASE_CONTROL` | 참가자 → 호스트 | 조작권 요청, 반납 |
| `VIEW_MODE` / `MODE_ACK` | 양방향 | 되감기·동기화·라이브 전환 요청과 확인. 기준·적용 완료 `seq` 포함, 조작권 부여와는 별개 |
| `CMD_PROPOSE` / `CMD_RESULT` | 양방향 | 명령 제안, 승인·거절·제출 결과 |
| `STATUS_QUERY` / `STATUS` | 양방향 | 참가자 목록, 조작자, 잠금, 녹화 상태 |
| `SIZE_REPORT` | 참가자 → 호스트 | 실제 터미널 크기 변경 알림 |
| `BYE` / `ERROR` | 양방향 | 정상 종료, 오류 |

## 14. 녹화 형식과 재생

```text
헤더:
  magic[6] = "TMREC2"
  version:u16 | rows:u16 | cols:u16
  start_unix_us:u64 | term_len:u16 | term:bytes

레코드:
  seq:u64 | elapsed_us:u64 | kind:u8 | actor_id:u32 | length:u32 | data:bytes
```

`elapsed_us`는 `CLOCK_MONOTONIC` 기준의 세션 경과 시간이고, 실제 시각은 헤더에 따로 둔다.

| kind | 내용 |
|---|---|
| `O` | PTY 출력 바이트 |
| `C` | 조작권 변경 (새 조작자, epoch) |
| `P` | 참가자 입장·퇴장, 표시 이름 |
| `G` | 호스트 전용 잠금·해제 |
| `M` | 명령 제안의 승인·거절 (본문은 저장하지 않음) |
| `R` | 화면 크기 변경 (확장 버전에서만) |
| `E` | 정상 종료 |

- 원시 키 입력 레코드는 없다. 재생 화면의 "조작자" 표시는 그 구간의 조작권 보유자를 뜻한다.
- 시간 색인으로 목표 시점의 레코드 위치를 찾는다. `lseek`는 읽기 시작점 이동에 쓰고, 화면은 초기 상태부터 목표 시점까지 재적용해 만든다.
- 알 수 없는 버전, 잘못된 길이, 깨진 순서를 검사한다. 비정상 종료된 파일은 마지막 완전한 레코드까지 재생하고 불완전함을 알린다.

## 15. 동시 처리, 오류, 종료

### 동시 처리와 자원 상한

- 모든 소켓과 PTY는 nonblocking이다. 부분 `read`·`write`, `EINTR`, `EAGAIN`, 연결 종료를 처리한다.
- 참가자마다 송신 대기량 상한을 둔다. 따라잡지 못해 상한을 넘은 참가자만 이유를 알리고 끊는다. 다른 참가자와 셸은 계속 동작한다.
- **메모리 로그 상한 64 MiB.** 헤더와 종료 정보 공간을 미리 확보하고, 남은 공간만큼만 PTY 출력을 읽는다. 상한에 가까워지면 경고하고, 도달하면 PTY 읽기와 새 입력을 멈춰 세션 종료와 새 세션 시작을 안내한다. 로그 앞부분을 몰래 버리지 않는다.
- **녹화 실패:** 파일 오류나 기록 큐 포화 시 파일 녹화만 실패 상태로 멈추고 알린다. 녹화가 안 되는데 정상처럼 표시하지 않는다. 메모리 로그 기반 되감기는 계속된다.

### 시그널과 종료

- 시그널 핸들러는 플래그를 세우고 self-pipe에 한 바이트를 쓰기만 한다. 실제 처리는 메인 루프에서 한다.
- `SIGCHLD`: 셸 종료를 `waitpid`로 회수하고 세션을 정리한다.
- `SIGWINCH`: 실제 터미널 크기를 다시 읽어 세션 크기와 비교한다.
- `SIGINT`, `SIGTERM`: 참가자에게 `BYE`를 보내고, 자식 셸을 정리하고, 녹화를 마무리하고, 터미널 설정을 복구한다.
- `SIGPIPE`: 무시하고 `write`의 `EPIPE`로 처리한다.
- `SIGKILL`처럼 정리 코드를 실행할 수 없는 종료 뒤에는 터미널이 raw 모드로 남을 수 있다. 이때는 `stty sane` 또는 `reset`으로 복구한다.

## 16. 사용하는 시스템 기술

| 영역 | API | 용도 |
|---|---|---|
| 프로세스·PTY | `forkpty`, `execvp`, `waitpid`, `kill` | 셸 실행, 종료 회수와 정리 |
| 터미널 | `tcgetattr`, `tcsetattr`, `ioctl` | raw 모드와 복구, 셸 쪽 입력 모드 조회, 화면 크기 |
| 시그널 | `sigaction`, `pipe` (self-pipe) | 자식 종료·크기 변경·종료 요청을 메인 루프로 전달 |
| 네트워크 | `socket`, `bind`, `listen`, `accept`, `connect`, `setsockopt` | 세션 생성과 참가, 통신 |
| 다중 I/O | `poll`, `fcntl` | nonblocking PTY·소켓을 한 루프에서 처리 |
| 스레드 | `pthread_create`, mutex, condition variable, 알림 `pipe` | 참가자 수신·화면 분리, 짧은 로그 잠금과 수신 알림, 호스트 기록 큐 |
| 파일 | `open`, `read`, `write`, `close`, `lseek` | 녹화, 재생, 시간 색인 |
| 시간 | `clock_gettime` | 이벤트 시각, 재생 속도 |
| UI | ncurses, ANSI 제어 | 명령·재생 화면 |

`forkpty`, pthread, ncurses는 라이브러리 함수다. 시스템콜로는 `socket`, `accept`, `read`, `write`, `ioctl`, `poll`, `open`, `lseek`, `waitpid` 등을 실제 기능에 사용한다.

| 파일 재생 | 정상·불완전 파일, 배속, 탐색 | 검증과 재구성, 손상 범위 표시 |

### 발표 시연 흐름

**필수 기능**

1. 호스트 A가 세션을 열고, B와 C의 입장을 승인한다. 셋이 같은 컴파일 오류를 본다.
2. B가 조작권을 요청한다. 승인 전 입력은 반영되지 않고, 승인 후 오류를 고친다.
3. C는 수정 과정을 놓쳤다고 가정하고 되감기를 시작한다.
4. A·B는 컴파일과 실행을 계속한다. C의 화면만 과거를 보여준다.
5. C가 라이브로 복귀해 현재 화면에 합류한다.

**추가 기능**

6. C가 `rm -r build`를 제안하고 A가 검토 후 거절한다.
7. A가 `sudo`를 실행하면 자동 잠금이 걸리고, 해제 후에도 조작권이 자동으로 돌아가지 않는 것을 보여준다.
8. 끝난 세션을 녹화 파일로 2배속 재생한다.

### 한계

| 항목 | 내용 |
|---|---|
| 화면 재현 | 같은 초기 상태·크기·호환 터미널과 검증된 프로그램 범위에서만 재현한다. 임의의 터미널과 모든 제어 명령의 재현은 범위 밖이다 |

| 명령 제안 | 주의 패턴은 검토 보조다. 별칭, 스크립트, 셸 확장까지 분석해 위험을 판정하지 않는다 |
| 민감 입력 추정 | 입력 모드는 비밀번호의 표준 신호가 아니다. 모든 비밀번호 입력을 잡지 못하고, 모드 변경과 입력 사이 경합이 있을 수 있다. 수동 잠금과 키 입력 미기록으로 보완한다 |
| 회수 | 이미 셸에 전달된 입력은 조작권을 회수해도 취소되지 않는다 |
| 보안 | 신뢰하는 팀원과 조교가 쓰는 LAN이 전제다. 세션 코드는 세션 확인용이며 강한 인증이 아니고, 통신은 암호화하지 않는다. 화면 내용은 공유되고 녹화된다. 키 입력 자체는 녹화하지 않는다 |
