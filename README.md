# TermMeet — 남에게 맡겨도 안전한 실습용 협업 터미널

> 여러 명이 내 터미널을 실시간으로 보고, 허락받은 한 명씩 조작하고, 위험한 순간은 자동으로 지킨다.

> 이 문서는 **설계 문서**다. 개발이 진행되면서 사용법과 구현 내용을 실제에 맞게 고쳐 나간다.

## 1. 소개

TermMeet는 터미널을 여러 사람이 함께 쓰는 프로그램이다. 화상회의 화면 공유는 영상이라 보기만 되지만, TermMeet는 터미널에 오가는 글자를 그대로 주고받기 때문에 **같이 조작**할 수 있다. 그리고 남에게 터미널을 맡겼을 때 생기는 위험(비밀번호 노출, 위험한 명령 실행)을 **프로그램이 자동으로 막는다.**

```
A (호스트)                         B (참가자)                        C (늦게 온 참가자)
$ termmeet host                    $ termmeet join <IP> 4821          $ termmeet join <IP> 4821
  세션 4821 · 참가자 2명           Ctrl+] r  → 조작권 요청            (5분 늦게 접속)
[B 조작권 요청 y/n] y              $ rm -rf build                     Ctrl+] b  → 되감기
[B: rm -rf build 실행?] n          → 호스트 승인 대기, 거절            놓친 부분을 혼자 재생
[비밀번호 입력 감지]               $ sudo apt install gdb             Ctrl+] l  → 라이브 복귀
 조작권 회수 → A                   [잠금] 비밀번호 입력 중
```

`vim`, `top`, `gdb`처럼 화면 전체를 쓰는 프로그램도 색과 커서 위치까지 똑같이 공유된다. 참가자는 여러 명 접속할 수 있고, 조작은 한 번에 한 명씩 한다.

### 해결하려는 문제

| 상황 | 지금 | TermMeet |
|---|---|---|
| 조교에게 질문 | 에러를 캡처해서 보내고 설명하기를 반복 | 조교가 내 터미널에 들어와 직접 보고 고친다 |
| 팀 프로젝트 | 한 명이 코드를 짜면 나머지는 보기만 | 조작권을 넘겨받아 이어서 작업한다 |
| 수업 시연 | 따라 치다 놓치면 다시 볼 수 없다 | 라이브 중에 놓친 부분만 되감아 본다 |
| 터미널을 남에게 맡길 때 | 공유 도구는 셸을 통째로 넘겨준다 | 비밀번호 입력과 위험 명령을 자동으로 지킨다 |

### 기존 도구와 차이

| | tmate, tty-share 등 | asciinema | **TermMeet** |
|---|---|---|---|
| 실시간 공유 | O | X | O |
| 조작권 요청·승인 | 링크로 권한 구분 | X | O (요청 → 승인 → 반납·회수) |
| 비밀번호 입력 보호 | X | X | **O** |
| 위험 명령 승인 | X | X | **O** |
| 녹화·재생 | 별도 도구 필요 | O | O (누가 쳤는지 포함) |
| 라이브 중 되감기 | X | X | **O** |

기존 오픈소스 코드는 가져오지 않고 모든 코드를 직접 작성한다.

## 2. 기능

| # | 기능 | 사용자가 하는 일 | 구분 |
|---|---|---|---|
| 1 | 세션 열기·참가 | 호스트가 세션 코드를 만들고, 여러 참가자가 IP와 코드로 접속 | 핵심 |
| 2 | 실시간 화면 공유 | 모두가 동시에 같은 터미널 화면을 본다 | 핵심 |
| 3 | 조작권 관리 | 요청 → 호스트 승인 → 넘기기·반납·회수 (조작은 한 번에 한 명) | 핵심 |
| 4 | **비밀번호 자동 보호** | 비밀번호 입력을 감지하면 조작권을 호스트에게 돌리고 입력 기록을 멈춘다 | 차별화 |
| 5 | **위험 명령 승인** | 참가자가 친 `rm -rf`, `sudo` 등은 호스트가 승인해야 실행된다 | 차별화 |
| 6 | **타임시프트** | 라이브를 받으면서 놓친 부분만 혼자 되감아 보고 다시 라이브로 복귀 | 차별화 |
| 7 | 창 크기 동기화 | 창 크기가 달라도 화면이 깨지지 않는다 | 확장 |
| 8 | 녹화·재생 | 누가 쳤는지 포함해 저장하고, 배속·건너뛰기로 재생 | 확장 |
| 9 | 상태 표시줄 | 조작자, 참가 인원, 보호 상태를 맨 아래 줄에 표시 | 확장 |

## 3. 사용법 (계획)

### 빌드

```bash
sudo apt install build-essential libncurses-dev
make
```

### 명령

```bash
./termmeet host [--port 7000] [--max 30] [--record session.rec] [--guard danger.txt]
./termmeet join <호스트 IP> <세션 코드> [--port 7000] [--name 이름]
./termmeet play <녹화 파일> [--speed 2]
```

| 옵션 | 의미 |
|---|---|
| `--port` | 접속 포트 (기본 7000) |
| `--max` | 최대 참가 인원 (기본 30) |
| `--record` | 세션을 파일로 녹화 |
| `--guard` | 위험 명령 패턴 목록 파일 (없으면 기본 목록 사용) |
| `--name` | 참가자 표시 이름 |
| `--speed` | 재생 배속 |

### 단축키

세션 안에서는 모든 키가 셸로 그대로 전달된다. TermMeet 명령은 **`Ctrl+]`를 누른 뒤 다음 키**로 쓴다.

| 키 | 동작 |
|---|---|
| `Ctrl+]` `r` | 조작권 요청 (참가자) |
| `Ctrl+]` `d` | 조작권 반납 |
| `Ctrl+]` `t` | 조작권 회수 (호스트) |
| `Ctrl+]` `b` | 되감기 모드 (타임시프트) |
| `Ctrl+]` `l` | 라이브로 복귀 |
| `Ctrl+]` `q` | 세션 나가기 (호스트는 세션 종료) |
| `Ctrl+]` `Ctrl+]` | `Ctrl+]` 자체를 셸로 보내기 |

되감기와 재생 화면에서는 `Space` 일시정지, `←` `→` 10초 이동, `+` `-` 배속 조절.

### 기본 위험 명령 패턴

`rm -rf`, `rm -r`, `sudo`, `su`, `shutdown`, `reboot`, `mkfs`, `dd`, `chmod -R`, `chown -R`, `> /dev/` 로 시작하거나 포함하는 명령. `--guard` 파일에 한 줄에 하나씩 적어 바꿀 수 있다.

## 4. 구조

### 전체 그림

```
                        ┌───────────────────── TermMeet 호스트 ─────────────────────┐
 호스트 키보드 ───────▶ │                                                            │
 참가자 B 키보드 ─TCP─▶ │ ① 입력 관문 ─▶ ② 보안 감시 ─────────────────────▶ pty ──▶ │ bash
 참가자 C 키보드 ─TCP─▶ │   (조작권 확인)  (비밀번호 상태, 위험 명령 검사)           │ (vim, gcc, gdb ...)
                        │                                                            │
                        │ ③ 출력 분배 ◀───────────────────────── 화면 출력 ── pty ◀─ │
                        │    ├─▶ 호스트 화면                                         │
                        │    ├─▶ 참가자들 (TCP)                                      │
                        │    └─▶ ④ 기록: 녹화 파일 + 타임시프트용 출력 로그          │
                        └────────────────────────────────────────────────────────────┘
```

1. 호스트가 `forkpty()`로 가상 터미널(pty)을 만들고 그 안에서 셸을 실행한다.
2. 입력은 **조작권을 가진 사람의 키만** 통과하고, pty로 넘어가기 전에 보안 감시를 거친다.
3. 셸이 출력한 바이트는 모두 호스트로 들어와 호스트 화면, 모든 참가자, 출력 로그로 복사된다.
4. 화면 출력에는 색과 커서 이동 명령(ANSI 이스케이프)이 들어 있으므로, 참가자는 받은 바이트를 자기 터미널에 그대로 쓰기만 하면 같은 화면이 된다.

### 호스트의 이벤트 처리

호스트는 하나의 `poll()` 루프로 여러 입력을 동시에 감시한다.

| 감시 대상 | 이벤트 | 처리 |
|---|---|---|
| pty 마스터 | 셸 출력 | 화면 출력, 참가자 전송, 로그 기록, 비밀번호 상태 확인 |
| 표준 입력 | 호스트 키 입력 | `Ctrl+]` 명령이면 처리, 아니면 조작권 있을 때 pty로 |
| 리슨 소켓 | 새 참가자 | `accept` 후 참가자 스레드 생성 |
| 참가자 소켓 | 참가자 메시지 | 참가자 스레드가 읽어 공유 큐에 넣음 |
| self-pipe | 시그널 발생 | `SIGWINCH`, `SIGCHLD`를 루프에서 안전하게 처리 |

참가자 목록과 조작권 상태는 여러 스레드가 함께 쓰므로 `pthread_mutex`로 보호한다.

## 5. 차별화 기능 설계

### 비밀번호 자동 보호

- `sudo`, `passwd`, `ssh`가 비밀번호를 물을 때 셸 쪽 터미널은 **ICANON은 켜고 ECHO만 끈다.**
- 리눅스에서는 pty **마스터** fd에 `tcgetattr()`를 하면 셸 쪽(슬레이브) 설정을 읽을 수 있다. 호스트는 셸 출력이 올 때마다 이 상태를 확인한다.
- `vim`, `less` 같은 전체 화면 프로그램은 ICANON과 ECHO를 **둘 다** 끄므로, "ICANON 켜짐 + ECHO 꺼짐"일 때만 비밀번호 입력으로 판단한다.
- 감지하면
  1. 조작권을 호스트에게 자동으로 돌린다.
  2. 참가자 상태 표시줄에 `[잠금] 비밀번호 입력 중`을 띄운다.
  3. 녹화 파일에 입력 기록을 남기지 않는다.
- ECHO가 다시 켜지면 원래 상태로 돌아간다.

### 위험 명령 승인

- 참가자의 입력은 pty로 넘기면서 동시에 **한 줄 버퍼**에 모은다. 백스페이스(0x7F)는 버퍼에서도 지운다.
- Enter(`\r`)가 오면 버퍼의 명령을 위험 패턴과 비교한다.
  - 안전하면 Enter를 pty로 넘긴다.
  - 위험하면 Enter를 **넘기지 않고 붙잡아 둔 채** 호스트에게 승인 창을 띄운다. 승인하면 Enter를 넘기고, 거절하면 `Ctrl-U`(0x15)를 보내 셸의 입력 줄을 지운다.
- 한계: Tab 자동완성이나 화살표로 불러온 명령은 버퍼에 글자가 안 들어와 놓칠 수 있다. 처음에는 **직접 친 명령의 기본 패턴 감지**부터 구현하고, 시간이 되면 범위를 넓힌다.

### 타임시프트

- 핵심 원리: 터미널 화면은 **지금까지의 출력 바이트를 처음부터 다시 그리면 똑같이 복원된다.**
- 호스트는 세션 출력 전체를 로그로 쌓는다. 참가자가 접속하면 그때까지의 로그를 먼저 받아 빠르게 그려서 현재 화면을 맞춘다. (늦은 참가자 문제 해결)
- 참가자가 되감기를 누르면 자기 컴퓨터에 쌓인 로그를 원하는 지점까지 다시 그려서 보여준다. 그동안 들어오는 라이브 출력은 로그에 계속 쌓아 둔다.
- 라이브로 복귀하면 화면을 지우고 로그 전체를 빠르게 다시 그려 현재 화면으로 돌아간다.
- 호스트와 다른 참가자의 화면에는 영향이 없다.

## 6. 통신 프로토콜

모든 메시지는 같은 헤더를 가진다.

```
+--------+------------------------------------+------------------+
| type   | length                             | payload          |
| 1 byte | 4 bytes (네트워크 바이트 순서)     | length bytes     |
+--------+------------------------------------+------------------+
```

| type | 이름 | 방향 | payload |
|---|---|---|---|
| 1 | `HELLO` | 참가자 → 호스트 | 세션 코드, 이름, 창 크기 |
| 2 | `WELCOME` | 호스트 → 참가자 | 참가자 번호, 현재 창 크기 |
| 3 | `REJECT` | 호스트 → 참가자 | 거절 이유 (코드 틀림, 인원 초과) |
| 4 | `HISTORY` | 호스트 → 참가자 | 접속 전까지의 출력 로그 |
| 5 | `OUTPUT` | 호스트 → 참가자 | 셸 화면 출력 바이트 |
| 6 | `INPUT` | 참가자 → 호스트 | 키 입력 바이트 (조작권 있을 때만 반영) |
| 7 | `REQ_CONTROL` | 참가자 → 호스트 | 없음 |
| 8 | `CONTROL` | 호스트 → 모두 | 현재 조작자 번호 |
| 9 | `GUARD` | 호스트 → 모두 | 보호 상태 (비밀번호 입력 중, 승인 대기 중인 명령) |
| 10 | `RESIZE` | 양방향 | 창 크기 (rows, cols) |
| 11 | `STATUS` | 호스트 → 모두 | 참가 인원, 조작자, 녹화 여부 |
| 12 | `BYE` | 양방향 | 없음 |

## 7. 녹화 파일 형식

```
헤더:   "TMREC1" (6 bytes) | rows (2) | cols (2) | 시작 시각 (8)
레코드: kind (1) | delay_ms (4) | who (1) | length (4) | data (length)
```

| kind | 의미 |
|---|---|
| `O` | 화면 출력 바이트 |
| `I` | 입력 바이트와 친 사람(`who`) — 비밀번호 입력 중에는 기록하지 않음 |
| `C` | 조작권 변경 (누가 받았는지) |

- `delay_ms`는 앞 레코드와의 시간 간격이다. 이 간격만큼 기다렸다가 출력하면 원래 속도, 간격을 배속으로 나누면 빨리 감기가 된다.
- 건너뛰기는 레코드 위치를 기록해 둔 색인으로 `lseek`해서 구현한다.
- 재생할 때 `C` 레코드로 "지금 B가 조작 중"을 표시한다.

## 9. 그 밖의 기법

### raw 모드 입력
`tcsetattr`로 `ICANON`, `ECHO`, `ISIG`를 끄고 한 바이트씩 읽는다. `Ctrl-C`, `Ctrl-Z`까지 셸로 그대로 넘기고, `Ctrl+]`(0x1D) 다음 키만 TermMeet 명령으로 해석한다. 종료할 때는 반드시 원래 터미널 설정을 복구한다 (`atexit`, 시그널 처리 포함).

### 동시 처리
pty와 소켓을 `poll`로 함께 감시하고, 참가자 목록은 뮤텍스로 보호한다. 느린 참가자 때문에 전체가 멈추지 않도록 참가자마다 전송 버퍼를 두고, 넘치면 그 참가자만 끊는다.

### 창 크기 차이
접속한 모든 사람 중 가장 작은 행·열 수로 pty 크기를 맞춘다(`ioctl(TIOCSWINSZ)`). 크기가 바뀌면 셸 쪽에 `SIGWINCH`가 가고 `vim` 같은 프로그램이 화면을 다시 그린다.

### 상태 표시줄
ANSI 스크롤 영역(`ESC[1;Nr`)으로 맨 아래 한 줄을 비워 두고, pty에는 행 수를 하나 적게 알려준다.

## 12. 위험과 대비

| 위험 | 대비 |
|---|---|
| WSL2는 기본 NAT라서 다른 노트북이 WSL 안으로 접속하지 못한다 | `%USERPROFILE%\.wslconfig`에 `networkingMode=mirrored`, 또는 Ubuntu VM 브리지 네트워크 |
| 학교 와이파이가 기기 간 통신을 막는다 | 휴대폰 핫스팟에 노트북을 연결해서 시연 |
| 네트워크 없이 개발해야 할 때 | 한 대에서 터미널 창 여러 개로 `127.0.0.1`에 접속해 테스트 |
| Tab·화살표로 만든 명령은 위험 명령 검사가 놓칠 수 있다 | 기본 패턴 감지부터 구현, 한계를 발표에서 밝힘 |
| 비정상 종료 시 터미널이 raw 모드로 남는다 | 종료 경로마다 설정 복구, 그래도 남으면 `reset` |
