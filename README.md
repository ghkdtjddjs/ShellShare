# TermMeet — 터미널판 줌

> 내 터미널을 여러 사람이 실시간으로 보고, 허락하면 같이 조작하는 프로그램

> 이 문서는 **설계 문서**다. 개발이 진행되면서 사용법과 구현 내용을 실제에 맞게 고쳐 나간다.

## 1. 소개

TermMeet는 터미널 화면을 공유하는 도구다. 화상회의 화면 공유는 영상을 보내서 **보기만** 되지만, TermMeet는 터미널에 오가는 글자를 그대로 주고받기 때문에 **같이 조작**할 수 있다.

```
노트북 A (호스트)                      노트북 B, C (참가자)
$ termmeet host                        $ termmeet join 192.168.0.5 4821
  세션 코드: 4821                        → A의 터미널이 그대로 보인다
$ vim hello.c                          Ctrl+] r  → 조작권 요청
[B가 조작권을 요청합니다 (y/n)] y        → B가 이어서 타이핑
$ gcc hello.c && ./a.out               → 모두에게 실행 결과가 보인다
```

`vim`, `top`, `gdb`처럼 화면 전체를 쓰는 프로그램도 색과 커서 위치까지 똑같이 공유된다.

### 이런 상황에 쓴다

| 상황 | 지금 | TermMeet |
|---|---|---|
| 조교에게 질문 | 에러를 캡처해서 보내고 설명하기를 반복 | 조교가 내 터미널에 들어와 직접 보고 고친다 |
| 팀 프로젝트 | 한 명이 코드를 짜면 나머지는 옆에서 보기만 | 조작권을 넘겨받아 이어서 작업한다 |
| 수업 시연 | 따라 치다 놓치면 다시 볼 수 없다 | 녹화본을 배속으로 다시 본다 |

### 기존 도구와 차이

- `tmate`(터미널 공유), `asciinema`(터미널 녹화)가 있지만 기능이 따로 나뉘어 있다. TermMeet는 **조작권 요청과 승인, 강의 모드, 녹화와 재생**을 교육 상황에 맞게 하나로 합친다.
- 이전 학기 Web Streamer는 웹 화면을 이미지로 공유했다. TermMeet는 **터미널 프로그램 자체**를 공유하고 조작한다.
- 기존 오픈소스 코드는 가져오지 않고 모든 코드를 직접 작성한다.

## 2. 기능

| # | 기능 | 사용자가 하는 일 | 구분 |
|---|---|---|---|
| 1 | 세션 열기·참가 | 호스트가 세션 코드를 만들고, 참가자는 IP와 코드로 접속 | 핵심 |
| 2 | 실시간 화면 공유 | 여러 명이 동시에 같은 터미널 화면을 본다 | 핵심 |
| 3 | 조작권 관리 | 요청 → 호스트 승인 → 넘기기·반납·회수, 보기 전용 | 핵심 |
| 4 | 창 크기 동기화 | 창 크기가 달라도 화면이 깨지지 않게 맞춘다 | 확장 |
| 5 | 세션 녹화 | 화면 출력과 시간 간격을 파일로 저장한다 | 확장 |
| 6 | 녹화 재생 | 배속, 일시정지, 건너뛰기로 다시 본다 | 확장 |
| 7 | 상태 표시줄·채팅 | 맨 아래 줄에 조작자, 참가 인원, 짧은 메시지를 표시 | 확장 |
| 8 | 강의 모드 | 호스트만 조작하고 참가자는 손들기만 가능 | 확장 |

## 3. 사용법 (계획)

### 빌드

```bash
sudo apt install build-essential libncurses-dev
make
```

### 명령

```bash
./termmeet host [--port 7000] [--record session.rec] [--lecture]
./termmeet join <호스트 IP> <세션 코드> [--port 7000] [--name 이름]
./termmeet play <녹화 파일> [--speed 2]
```

| 옵션 | 의미 |
|---|---|
| `--port` | 접속 포트 (기본 7000) |
| `--record` | 세션을 파일로 녹화 |
| `--lecture` | 강의 모드: 조작권 요청 대신 손들기만 허용 |
| `--name` | 참가자 표시 이름 |
| `--speed` | 재생 배속 |

### 단축키

세션 안에서는 모든 키가 셸로 그대로 전달된다. TermMeet 명령은 **`Ctrl+]`를 누른 뒤 다음 키**로 쓴다.

| 키 | 동작 |
|---|---|
| `Ctrl+]` `r` | 조작권 요청 (참가자) / 손들기 (강의 모드) |
| `Ctrl+]` `d` | 조작권 반납 |
| `Ctrl+]` `t` | 조작권 회수 (호스트) |
| `Ctrl+]` `c` | 채팅 한 줄 입력 |
| `Ctrl+]` `q` | 세션 나가기 (호스트는 세션 종료) |
| `Ctrl+]` `Ctrl+]` | `Ctrl+]` 자체를 셸로 보내기 |

재생 화면에서는 `Space` 일시정지, `←` `→` 10초 이동, `+` `-` 배속 조절, `q` 종료.

## 4. 구조

### 전체 그림

```
                        ┌──────────────── TermMeet 호스트 ────────────────┐
 호스트 키보드 ───────▶ │                                                  │
 참가자 B 키보드 ─TCP─▶ │ ① 입력 관문 ── 조작권 있는 사람 키만 ──▶ pty ──▶ │ bash
 참가자 C 키보드 ─TCP─▶ │                                                  │ (vim, gcc, gdb ...)
                        │ ② 출력 분배 ◀──────────── 화면 출력 ── pty ◀──── │
                        │    ├─▶ 호스트 화면                               │
                        │    ├─▶ 참가자 B, C (TCP)                         │
                        │    └─▶ ③ 녹화 파일 (시간 정보와 함께)            │
                        └──────────────────────────────────────────────────┘
```

1. 호스트가 `forkpty()`로 가상 터미널(pty)을 만들고 그 안에서 셸을 실행한다.
2. 셸이 출력한 바이트는 모두 호스트로 들어온다. 호스트는 그것을 자기 화면에 쓰고, 모든 참가자에게 보내고, 녹화 파일에 쓴다.
3. 입력은 반대 방향이다. 조작권을 가진 사람의 키만 pty로 넘긴다.
4. 화면 출력에는 색과 커서 이동 명령(ANSI 이스케이프)이 들어 있으므로, 참가자는 받은 바이트를 자기 터미널에 그대로 쓰기만 하면 같은 화면이 된다.

### 호스트의 이벤트 처리

호스트는 하나의 `poll()` 루프로 여러 입력을 동시에 감시한다.

| 감시 대상 | 이벤트 | 처리 |
|---|---|---|
| pty 마스터 | 셸 출력 | 화면 출력, 모든 참가자에게 전송, 녹화 |
| 표준 입력 | 호스트 키 입력 | `Ctrl+]` 명령이면 처리, 아니면 조작권 있을 때 pty로 |
| 리슨 소켓 | 새 참가자 | `accept` 후 참가자 스레드 생성 |
| 참가자 소켓 | 참가자 메시지 | 참가자 스레드가 읽어 공유 큐에 넣음 |
| self-pipe | 시그널 발생 | `SIGWINCH`, `SIGCHLD`를 루프에서 안전하게 처리 |

참가자 목록과 조작권 상태는 여러 스레드가 함께 쓰므로 `pthread_mutex`로 보호한다.

## 5. 통신 프로토콜

모든 메시지는 같은 헤더를 가진다.

```
+--------+------------------+---------------------+
| type   | length           | payload             |
| 1 byte | 4 bytes (네트워크 바이트 순서) | length bytes |
+--------+------------------+---------------------+
```

| type | 이름 | 방향 | payload |
|---|---|---|---|
| 1 | `HELLO` | 참가자 → 호스트 | 세션 코드, 이름, 창 크기(rows, cols) |
| 2 | `WELCOME` | 호스트 → 참가자 | 참가자 번호, 현재 창 크기 |
| 3 | `REJECT` | 호스트 → 참가자 | 거절 이유 (코드 틀림, 인원 초과) |
| 4 | `OUTPUT` | 호스트 → 참가자 | 셸 화면 출력 바이트 |
| 5 | `INPUT` | 참가자 → 호스트 | 키 입력 바이트 (조작권 있을 때만 반영) |
| 6 | `REQ_CONTROL` | 참가자 → 호스트 | 없음 |
| 7 | `CONTROL` | 호스트 → 모두 | 현재 조작자 번호 |
| 8 | `RESIZE` | 양방향 | 창 크기(rows, cols) |
| 9 | `CHAT` | 양방향 | 보낸 사람, 메시지 |
| 10 | `STATUS` | 호스트 → 모두 | 참가 인원, 조작자, 녹화 여부 |
| 11 | `BYE` | 양방향 | 없음 |

## 6. 녹화 파일 형식

```
헤더:  "TMREC1" (6 bytes) | rows (2) | cols (2) | 시작 시각 (8)
레코드: delay_ms (4) | length (4) | 출력 바이트 (length)
레코드: ...
```

- `delay_ms`는 앞 레코드와의 시간 간격이다. 재생할 때 이 간격만큼 기다렸다가 출력하면 원래 속도가 되고, 간격을 배속으로 나누면 빨리 감기가 된다.
- 건너뛰기는 레코드 위치를 기록해 둔 색인으로 `lseek`해서 구현한다.

## 8. 핵심 기법과 해결 방법

### raw 모드 입력
- **문제:** `Ctrl-C`, `Ctrl-Z`까지 셸로 넘겨야 하지만 TermMeet를 끄는 키도 필요하다.
- **해결:** `tcsetattr`로 `ICANON`, `ECHO`, `ISIG`를 끄고 한 바이트씩 읽는다. `Ctrl+]`(0x1D) 다음 키만 TermMeet 명령으로 해석한다. 종료할 때는 반드시 원래 터미널 설정을 복구한다 (`atexit`, 시그널 처리 포함).

### 동시 처리
- **문제:** 참가자가 들어오고 나가는 중에도 화면 전송이 끊기면 안 된다.
- **해결:** pty와 소켓을 `poll`로 함께 감시하고, 참가자 목록은 뮤텍스로 보호한다. 느린 참가자 때문에 전체가 멈추지 않도록 참가자마다 전송 버퍼를 두고, 넘치면 그 참가자만 끊는다.

### 중간 참가자
- **문제:** 늦게 들어온 사람은 이전 화면이 없어서 화면이 깨져 보인다.
- **해결:** 참가자가 접속하면 pty 크기를 잠깐 바꿨다가 되돌린다. `ioctl(TIOCSWINSZ)`가 셸 쪽에 `SIGWINCH`를 보내고, `vim` 같은 프로그램은 이 신호를 받으면 화면 전체를 다시 그린다.

### 창 크기 차이
- **문제:** 참가자 창이 호스트보다 작으면 줄이 어긋난다.
- **해결:** 접속한 모든 사람 중 가장 작은 행·열 수로 pty 크기를 맞춘다. 누가 창 크기를 바꾸면 `RESIZE`를 보내고 다시 계산한다.

### 상태 표시줄
- **문제:** 셸 출력이 화면 전체를 쓰면 상태 표시줄이 지워진다.
- **해결:** ANSI 스크롤 영역(`ESC[1;Nr`)으로 맨 아래 한 줄을 비워 두고, pty에는 행 수를 하나 적게 알려준다.

## 9. 파일 구성 (계획)

| 파일 | 역할 |
|---|---|
| `main.c` | 명령 분기 (`host`, `join`, `play`) |
| `host.c` | pty 생성, 셸 실행, `poll` 루프 |
| `server.c` | 리슨 소켓, 참가자 스레드, 참가자 목록 |
| `client.c` | 참가자 쪽 접속, 출력 표시, 입력 전송 |
| `protocol.c/.h` | 메시지 헤더, 보내기·받기 |
| `control.c` | 조작권 요청, 승인, 회수, 강의 모드 |
| `term.c` | raw 모드 설정과 복구, 창 크기, 상태 표시줄 |
| `record.c` | 녹화 파일 쓰기 |
| `play.c` | 녹화 재생 (ncurses) |
| `Makefile` | 빌드 (`-lutil -lpthread -lncurses`) |

## 10. 개발 일정과 역할

| 주차 | 목표 |
|---|---|
| 1주 (11/10~) | pty로 셸을 감싸고 raw 모드로 혼자 쓰기 |
| 2주 (11/17~) | 소켓 1:N 화면 공유, 참가·퇴장 처리 |
| 3주 (11/24~) | 조작권, 창 크기 동기화, 상태 표시줄 |
| 4주 (12/1~) | 녹화·재생, 강의 모드, 시연 준비 |

발표일(12/1 또는 12/8)에 맞춰 조정한다. 1주 차가 끝나면 핵심 원리가 증명되고, 이후는 기능을 하나씩 얹는 구조라 일정이 밀려도 동작하는 결과물이 남는다.

| 담당 | 역할 |
|---|---|
| [이름] | 호스트 쪽: pty, raw 모드, 창 크기, 녹화·재생 |
| [이름] | 네트워크 쪽: 서버·클라이언트, 프로토콜, 조작권, 채팅·상태 표시줄 |

## 11. 위험과 대비

| 위험 | 대비 |
|---|---|
| WSL2는 기본 NAT라서 다른 노트북이 WSL 안으로 접속하지 못한다 | `%USERPROFILE%\.wslconfig`에 `networkingMode=mirrored` 설정, 또는 Ubuntu VM 브리지 네트워크 |
| 학교 와이파이가 기기 간 통신을 막는다 | 휴대폰 핫스팟에 노트북을 연결해서 시연 |
| 네트워크 없이 개발해야 할 때 | 노트북 한 대에서 터미널 창 여러 개로 `127.0.0.1`에 접속해 테스트 |
| 프로그램이 비정상 종료되면 터미널이 raw 모드로 남는다 | 종료 경로마다 설정 복구, 그래도 남으면 `reset` 명령 |

## 12. 개발 환경

- OS: Ubuntu 24.04
- 언어: C (gcc)
- 라이브러리: glibc (`forkpty`는 `<pty.h>`, `-lutil`), pthread, ncurses
